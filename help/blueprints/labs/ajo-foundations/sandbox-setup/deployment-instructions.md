# 部署指示

>[!WARNING]
>
>只有在您按照自己的進度進行Labs時，才需要這樣做。 如果您正在參加即時培訓課程或活動，您的沙箱已為您部署。

AJO架構基礎實驗室套件會使用DEP CLI部署到您的沙箱，這個命令列工具會建立您將在實驗室使用的結構描述、資料集、資料流和範例資料，涵蓋設定檔存放區以及用於協調行銷活動的AJO關聯式存放區。

## 部署內容

**設定檔曲目**

- 身分識別名稱空間(customerID、planID、productID)
- 為設定檔啟用的標準XDM欄位群組、描述項和結構描述
- 為設定檔啟用的目錄資料集
- 合併原則和對象
- 三個範例資料集的設定檔資料：深層模式（特徵+事件）、陌生事物（特徵）和決策（特徵）

**關聯式曲目**

- customerID身分名稱空間
- 具有主索引鍵、外部索引鍵和版本描述項的11個關聯式XDM結構描述
- 為AJO協調的行銷活動啟用11個資料集
- 11個資料流從資料登陸區域載入資料

>[!NOTE]
>
>端對端部署大約需要2小時23分鐘。 設定檔和關聯式追蹤會平行執行，而且大部分時間都是CLI自動執行的自動等待時間。

## 先決條件

- **授權權益。** 具有Real-Time CDP （含串流分段）和Adobe Journey Optimizer （含協調行銷活動）的IMS組織的管理許可權
- **存取許可權。** 具有目標沙箱上所有許可權的Experience Platform角色，包括您從[Developer Console安裝程式](developer-console-setup.md)建立的API認證。
- **Developer Console認證。** 同時包含Adobe Experience Platform API和Adobe Journey Optimizer API的專案。 如果您還沒有這些專案，請先依照[Developer Console設定](developer-console-setup.md)操作
- **沙箱。** 空白，型別為`dev`，且在「就緒」狀態中至少持續120分鐘，然後再開始部署
- **Node.js.** 任何最新的LTS版本，在Windows或Mac上

## &#x200B;1. 安裝CLI

1. 複製或下載[dep-cli存放庫](https://github.com/adobe/dep-cli)
1. 從`dep-cli`目錄，執行`npm install`
1. 使用`npm start`啟動CLI

>[!NOTE]
>
>執行上述命令前需要Node.js。 如果您尚未安裝Node.js，請先參閱Wiki的[Node.js安裝程式](https://github.com/adobe/dep-cli/wiki/Nodejs-Setup)頁面。 如需完整的安裝詳細資料，包括熒幕擷取畫面以及如何更新現有安裝，請參閱[安裝](https://github.com/adobe/dep-cli/wiki/Installation)Wiki頁面

## &#x200B;2. 設定您的環境檔案

CLI會部署到您的環境檔案指向的任何沙箱，因此這必須在您執行任何操作之前正確設定。

1. 複製`envFiles/sample-env.json`並賦予其新名稱，例如`my-env.json`
2. 開啟檔案，並使用[Developer Console設定](developer-console-setup.md)中的值填入下列欄位：

   | **欄位** | **值** |
   | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `API_KEY` | 使用者端ID |
   | `CLIENT_SECRET` | 使用者端密碼 |
   | `IMS_ORG` | 組織ID |
   | `SCOPES` | 必須包括Experience Platform API和Adobe Journey Optimizer API範圍&#x200B;<br />*（例如cjm.suppression\_service.client.delete、cjm.suppression\_service.client.all、openid、session、AdobeID、read\_organizations、additional\_info.projectedProductContext）* |
   | `SANDBOX_NAME` | 您定位的沙箱 — 必須為空白且型別為`dev` |

3. 儲存並關閉檔案

>[!NOTE]
>
>每次執行CLI命令時，都會提示您輸入此檔案的名稱，這樣您便可以在下列的每一個步驟中重複使用它。

## &#x200B;3. 執行AJO架構基礎功能表

從主功能表中選取&#x200B;**AJO arch foundation**。 分為六個步驟，分屬兩個軌道。

### 設定檔追蹤（依順序執行）

>[!WARNING]
>
>在執行步驟1之前，沙箱必須處於至少60分鐘的「就緒」狀態。

| **步驟** | **它的作用** | **執行之前** |
| ------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------- |
| &#x200B;1. 建立設定檔基底 | 部署身分識別名稱空間、結構描述、資料集、合併原則和對象 | 沙箱「就緒」60分鐘以上 |
| &#x200B;2. 載入設定檔資料 | 建立資料流並串流深度模式、陌生事物和決策設定檔資料 | 步驟1後等待60分鐘以上 |
| &#x200B;3. 檢查設定檔健康狀況 | 驗證所有設定檔資料皆已正確載入 | 在步驟2後等待15分鐘以上 |

步驟1大約需要2分鐘，步驟2大約需要6分鐘。

>[!NOTE]
>
>如果發生問題，可以安全地重新執行步驟2 — 它會覆寫現有特徵並略過重複事件。

### 關聯式追蹤

>[!WARNING]
>
>在執行步驟4或步驟6之前，沙箱必須處於至少120分鐘的「就緒」狀態。

| **步驟** | **它的作用** | **執行之前** |
| ----------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------- |
| &#x200B;4. 建立關聯式基礎 | 建立customerID名稱空間和關聯結構描述/描述項/資料集 | 沙箱「就緒」120分鐘以上 |
| &#x200B;5. 載入關聯式資料 | 上傳11個CSV檔案並建立載入這些檔案的資料流 | 在步驟4之後立即執行 — 不需要手動等待 |
| &#x200B;6. 部署關聯式基礎與資料 | 將步驟4和5結合為單一約5分鐘的回合 | 沙箱「就緒」120分鐘以上 |

>[!NOTE]
>
>使用步驟6，而不是分別執行步驟4和5 — 它會在一個階段中執行相同的動作，為您處理傳輸等待。

>[!NOTE]
>
>CLI會自動檢查上述所有等待時間。 如果您過早執行步驟，它會封鎖並告訴您要等待多久。

## 疑難排解

>[!WARNING]
>
>**設定檔健康情況檢查因缺少事件而失敗。** 部分設定檔資料尚未完成傳播。 請再等待15分鐘，然後重新執行檢查設定檔健康狀態。 如果仍然失敗，請重新執行載入設定檔資料，等待15分鐘，然後再次檢查。

>[!WARNING]
>
>**關聯式資料載入途中失敗。** 每個API呼叫最多會重試3次。 如果仍然失敗，清理會移除它建立的來源連線、目標連線和資料流，因此您可以幹淨地重新執行步驟5 （或步驟6）。 對應集無法透過API刪除，並且可能被留下 — 這不會影響重新部署。

**發生其他錯誤。** 您最後可以從CLI的沙箱管理選單重設沙箱，並從步驟1重新部署。

>[!CAUTION]
>
>重設沙箱具有破壞性。 CLI會要求您輸入沙箱名稱以進行確認，然後再繼續。
