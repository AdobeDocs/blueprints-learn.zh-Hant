# 講座

## 學習目標

- 說明內容（而非資料或歷程）為何是大規模個人化方案中的主要限制
- 說明四層內容解剖模型：資產、片段、範本和訊息
- 區分AJO片段和AEM內容片段，包括每個片段處理傳播的方式
- 對應建立、儲存、管理、控管、啟用和測量等內容生命週期階段
- 比較三種內容整合模式：AJO Standalone、AJO + AEM Assets和AJO + GenStudio for Performance Marketing
- 識別指示何時從一種模式提升到另一種模式的架構訊號
- 說明Adobe棧疊中的三層AI功能：內容助理、Firefly自訂模型和統一品牌服務
- 說明AI輔助內容工作流程中人在迴路中的監督原則
- 區分真正的個人化與名字插入或資產倍增

## 重要技巧

Personalization的規模取決於三個支柱：內容、資料和歷程。 大部分的企業在資料與歷程協調上投入巨資，但將內容視為事後考量，這正是個人化計畫首先中斷內容的原因。 對於AJO架構者而言，將可擴充實作與在其範本無序下摺疊的實作區分開來，是因為瞭解如何將內容結構為受管理的系統，而非一棧一次性資產。

**在本課程中，您已講到：**

- 論文：個人化不會因為資料而失敗，而是因為內容不是以系統架構而失敗
- 四層內容剖析：Assets （DAM中的原子媒體）、片段（可重複使用的視覺或運算式區塊）、範本（鎖定與可編輯區域）和訊息（最終組合、通道就緒輸出）
- 內容生命週期：建立、儲存、管理、控管、啟動、測量，以及略過一個階段時如何由左至右階層發生失敗
- 模式1，AJO獨立：最適合單一市場、單一管道、50種以下的變體，速度為主要限制時；使用AEM Assets Essentials作為基本套件式DAM
- AJO片段儲存在AJO中，以重複專案的形式複製到範本中，不會自動更新，且有30個片段/1個巢狀層級的限制
- 模式2， AJO + AEM：最適合多市場、50多種變體，當治理是主要限制時；AEM會成為記錄系統，AJO會成為啟用系統
- AEM內容片段由AJO參考（非複製），因此更新會立即傳播到每個參考範本、歷程和行銷活動
- 三種會無訊息中斷片段傳播的情況：繼承中斷（未鎖定的片段）、新增到已發佈片段的新個人化屬性，以及物件層級存取控制(OLAC)標籤限制
- 模式3、AJO + GenStudio for Performance Marketing：最適合生產規模和高容量變體產生；需要模式2治理作為硬性先決條件
- 讓AI世代延續至品牌的四大支柱：統一品牌服務、Content Credentials、人在迴路中組織以及AJO整合
- 架構決策矩陣與內容Supply chain成熟度模型（第1級隨選至5級自主作業），用於診斷使用者端目前的位置
- 真正的個人化是單一控管範本中的智慧型變數，而不是名字合併欄位或每個區段的個別行銷活動
