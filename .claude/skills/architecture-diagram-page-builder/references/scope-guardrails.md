# 範圍護欄：架構頁面與使用案例模式頁面

Blueprint網站將&#x200B;**架構圖表頁面**&#x200B;與&#x200B;**使用案例模式頁面**&#x200B;分開，因為它們滿足不同的讀取器需求。 本檔案會定義內容所屬的位置，以及如何處理跨越邊界的內容。

## 核心差異

- **架構圖表頁面**&#x200B;是頂層視覺參考。 他們回答： *「這些系統如何組合？ 整合點在哪裡？ 資料流程的形狀為何？&quot;* 讀者來這裡是為了瞭解自己的方向。
- **使用案例模式頁面**&#x200B;為實作指南。 他們回答： *「我如何建置此功能？ 這涉及哪些功能？ 哪些KPI可測量成功？ 我的實作選項為何？&quot;* 當讀者有使用案例並需要出貨時，他們就會來到這裡。

## 屬於架構頁面

| 類別 | 範例 |
| --- | --- |
| 頂層架構 | AEP和應用程式、Experience Cloud市場結構、集線器與Edge拓撲的概觀圖表 |
| 系統資料流程 | 即時與批次擷取路徑、中樞與邊緣之間的設定檔同步、查閱與啟用流程 |
| 整合點 | 其中AEP與AJO、CJA、Target、Campaign、Marketo、Workfront整合；SDK邊界；API介面 |
| 部署拓撲 | Web SDK與Mobile SDK部署、伺服器端轉送、邊緣節點放置的比較 |
| 應用程式架構 | 單一應用程式(AJO、CJA、RTCDP)如何在系統層級進行內部結構 |
| 使用案例模式的指標 | 「此架構支援具有連結的模式X、Y、Z」 — 架構頁面&#x200B;**不會**&#x200B;複製該內容 |

## 不屬於架構頁面

如果您發現自己正在撰寫下列任何內容，請重新導向至使用案例模式頁面（使用`use-case-pattern-builder`技能）：

| 類別 | 為什麼它屬於其他地方 |
| --- | --- |
| KPI和測量公式 | 使用案例模式會測量結果；架構頁面不會 |
| 業務目標、業務影響 | KBO內容存在於`/help/blueprints/business-objectives/`之下；模式參考它 |
| 戰術使用案例範例 | 「購物車放棄提醒」、「個人化首頁主圖」等 — 這些是模式內容 |
| 功能(`A > B > C > D`) | 功能建構是使用案例模式範本的一部分 |
| 角色敘述 | 「行銷人員想要……瑪利亞」 樣式案例屬於模式，而不是架構參照 |
| 實作選項 | 多選項實作指引（最適合、運作方式、優點、限制）是模式建構 |
| 基礎/支援函式表格 | 這些是模式頁面區段 |
| 每個使用案例的先決條件檢查清單 | 模式會追蹤這些專案；架構頁面會改為連結至模式 |

## 觸發要觀看的片語

如果使用者在描述新頁面時提供以下任何片語，請暫停並重新檢查範圍：

- &quot;KPIs&quot;
- 「業務影響」/「業務成果」
- 「戰術使用案例」/「範例情境」
- &quot;capabilities&quot;
- &quot;實作選項&quot;
- &quot;best for&quot;
- 「優點與限制」
- &quot;必要條件&quot;
- 「角色」/「利害關係人」
- 「測量」

這些不會自動取消頁面的資格，但表示使用者可能想要使用案例模式頁面，而不是架構頁面。 產生之前先確認目的。

## 內容漂移時該做什麼

1. **識別漂移。** 指向越過邊界的特定截面或專案符號。
2. **提供兩個選項給使用者：**
   - 從架構頁面修剪區段（最常見 — 讓架構頁面保持焦點）。
   - 停止並切換至該內容的`use-case-pattern-builder` （當使用者實際需要模式頁面時）。
3. **等待確認。** 請勿無訊息地重寫或捨棄內容。
4. **如果保留僅限架構的內容**，請在連結到相關模式（現有或即將建立）的`## Use case patterns supported`下，以單一專案符號取代深層內容。

## Edge案例

- **頁面是半架構，半模式。** 分割成兩個頁面 — 一個架構頁面（此技能）、一個使用案例模式頁面（`use-case-pattern-builder`技能）。 交叉連結這些專案。
- **架構頁面說明單一使用案例端對端。** 那是使用案例模式，而不是架構頁面。 重新導向至`use-case-pattern-builder`。
- **架構頁面必須顯示特定情境的範例資料流程。** 如果案例僅為說明性且頁面大部分停留在系統架構層級，則可接受。 將範例保留至一個段落，並連結至相關模式，以取得完整詳細資訊。

## 快速測試

產生之前，詢問： *「如果讀者進入此頁面，期待頂層架構參考，他們會得到一個嗎？還是會獲得一個完成一半的使用案例逐步解說？」* 如果是後者，則頁面屬於`use-case-pattern-builder`。
